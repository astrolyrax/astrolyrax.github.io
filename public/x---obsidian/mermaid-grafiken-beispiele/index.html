    Mermaid Grafiken Beispiele

    Gerne. Unten findest du 10 unterschiedliche Mermaid-Beispiele, die folgende Anforderungen erfüllen:

    • ✅ Waagerechte (LR) und senkrechte (TD/TB) Ausrichtungen
    • ✅ Farbige Knoten mit classDef
    • ✅ Beschriftete Verbindungen
    • ✅ Verzweigungen
    • ✅ Unterschiedliche Diagrammtypen und Strukturen

    Grafikelemente

    Form Bedeutung
    [ ] Prozess oder Eingabe
    ( ) Anwendung, Modell, Service
    { } Entscheidung
    [( )] Datenbank
    ([ ]) Start/Ende

    classDef

    Parameter Bedeutung
    fill Hintergrundfarbe
    color Textfarbe
    stroke Rahmenfarbe
    stroke-width Stärke des Rahmens

    Schriftformatierungen

    Parameter Bedeutung
    font-size Schriftgröße
    font-weight normal, bold
    font-family Schriftart
    font-style normal, italic

    Rahmenformatierungen

    • gestrichelter Rahmen
    classDef warning stroke-dasharray:5 5
    • gepunkteter Rahmen
    classDef warning stroke-dasharray:2 2
    • transparenter Hintergrund:
    classDef transparent fill-opacity:0.5
    • transparenter Text: Die Texttransparenz wird nicht von allen Mermaid-Versionen unterstützt.
    classDef transparent color:#000

    Beispiele:

    classDef process fill:#2196F3,
	color:#ffffff,
	stroke:#0D47A1,
	stroke-width:2px,
	font-weight:bold,
	font-size:16px

    typische Farbklassen

    • Start/Ende
    classDef start fill:#4CAF50,color:#fff,stroke:#2E7D32
    • Prozess
    classDef process fill:#2196F3,color:#fff,stroke:#1565C0
    • Entscheidung
    classDef decision fill:#FFC107,color:#000,stroke:#FF8F00
    • Datenbank
    classDef database fill:#9C27B0,color:#fff,stroke:#6A1B9A
    • Fehler
    classDef error fill:#F44336,color:#fff,stroke:#B71C1C
    • Empfehlung
    classDef teamlead fill:#1976D2,color:white,stroke:#0D47A1,stroke-width:2px

    komplette Beispiel mit Standard-Farbklassen

    flowchart TD    
	
	A([Start])  
	BO(Eingabe)
	B[Prozess]  
	C{Prüfung}  
	D[(Datenbank)]  
	E([ENDE])	
	
	A --> BO
	BO --> B
	B --> C
	C --> |i.O.| D
	C --> |n.i.O.| B
	D --> E 
  
	classDef start/ende fill:#1976D2,color:white,stroke:#0D47A1,stroke-width:2px  
	classDef eingabe fill:#4CAF50,color:white
	classDef process fill:#2196F3,color:white  
	classDef decision fill:#FFC107,color:black  
	classDef database fill:#9C27B0,color:white    
	
	class A,E start/ende
	class BO eingabe
	class B process
	class C decision
	class D database

    1. Einfacher Geschäftsprozess (horizontal)

    flowchart LR

    A[Anfrage] -->|prüfen| B{Vollständig?}
    B -->|Ja| C[Bearbeiten]
    B -->|Nein| D[Fehlende Daten anfordern]
    D -->|ergänzen| A
    C -->|abschließen| E[Erledigt]

    classDef start fill:#4CAF50,color:#fff
    classDef task fill:#2196F3,color:#fff
    classDef decision fill:#FF9800,color:#fff
    classDef finish fill:#9C27B0,color:#fff

    class A start
    class B decision
    class C,D task
    class E finish

    2. Ticketbearbeitung (vertikal)

    flowchart TD

    A[Ticket erstellt]
    B[Analyse]
    C{Lösung bekannt?}
    D[Sofort beheben]
    E[Experten einschalten]
    F[Ticket schließen]

    A -->|weiterleiten| B
    B -->|bewerten| C
    C -->|Ja| D
    C -->|Nein| E
    D -->|erledigt| F
    E -->|Lösung gefunden| F

    classDef blue fill:#03A9F4,color:#fff
    classDef orange fill:#FF9800,color:#fff
    classDef green fill:#4CAF50,color:#fff

    class A,B,D,E blue
    class C orange
    class F green

    3. Software-Deployment

    flowchart LR

    A[Code Commit]
    B[Build]
    C[Test]
    D{Tests erfolgreich?}
    E[Deployment]
    F[Fehler beheben]

    A -->|Start| B
    B -->|Artefakte| C
    C -->|Ergebnis| D
    D -->|Ja| E
    D -->|Nein| F
    F -->|Neuer Commit| A

    classDef process fill:#42A5F5,color:white
    classDef decision fill:#FFB300,color:black
    classDef deploy fill:#66BB6A,color:white

    class A,B,C,F process
    class D decision
    class E deploy

    4. Organigramm

    flowchart TB

    CEO[Geschäftsführung]

    CEO -->|leitet| IT[IT]
    CEO -->|leitet| HR[Personal]
    CEO -->|leitet| FIN[Finanzen]

    IT -->|verantwortet| DEV[Entwicklung]
    IT -->|verantwortet| OPS[Betrieb]

    classDef boss fill:#E91E63,color:#fff
    classDef dept fill:#2196F3,color:#fff
    classDef team fill:#4CAF50,color:#fff

    class CEO boss
    class IT,HR,FIN dept
    class DEV,OPS team

    5. Bestellprozess

    flowchart LR

    A[Kunde]
    B[Shop]
    C{Ware verfügbar?}
    D[Versand]
    E[Nachbestellung]

    A -->|Bestellung| B
    B -->|Lagerprüfung| C
    C -->|Ja| D
    C -->|Nein| E
    E -->|nach Lieferung| D

    classDef customer fill:#8E24AA,color:#fff
    classDef system fill:#1E88E5,color:#fff
    classDef decision fill:#FB8C00,color:#fff
    classDef action fill:#43A047,color:#fff

    class A customer
    class B system
    class C decision
    class D,E action

    6. Netzwerkarchitektur

    flowchart TD

    S([START])
    U[Benutzer]
    FW[Firewall]
    LB[Load Balancer]
    APP1[App Server 1]
    APP2[App Server 2]
    DB[(Datenbank)]
    E([ENDE])
	
	S --> U
    U -->|HTTPS| FW
    FW -->|weiterleiten| LB
    LB -->|Anfrage| APP1
    LB -->|Anfrage| APP2

    APP1 -->|SQL| DB
    APP2 -->|SQL| DB
    DB --> E

    classDef user fill:#8BC34A
    classDef network fill:#03A9F4,color:white
    classDef server fill:#673AB7,color:white
    classDef db fill:#F44336,color:white

    class U user
    class FW,LB network
    class APP1,APP2 server
    class DB db

    7. Bewerbungsprozess

    flowchart LR

    A[Bewerbung]
    B[Prüfung]
    C{Geeignet?}
    D[Interview]
    E[Absage]
    F[Einstellung]

    A -->|eingegangen| B
    B -->|bewertet| C
    C -->|Ja| D
    C -->|Nein| E
    D -->|positiv| F
    D -->|negativ| E

    classDef process fill:#2196F3,color:white
    classDef decision fill:#FFC107,color:black
    classDef success fill:#4CAF50,color:white
    classDef reject fill:#F44336,color:white

    class A,B,D process
    class C decision
    class F success
    class E reject

    8. Datenflussdiagramm

    flowchart TB

    ETL[ETL-Prozess]
    DWH[Data Warehouse]
    BI[BI-Tool]
    USER[Fachanwender]

    SRC -->|extrahieren| ETL
    ETL -->|transformieren| DWH
    DWH -->|Reports| BI
    BI -->|Visualisierung| USER

    classDef source fill:#00BCD4,color:white
    classDef process fill:#3F51B5,color:white
    classDef target fill:#4CAF50,color:white

    class SRC source
    class ETL,BI process
    class DWH,USER target

    9. Eskalationsprozess

    flowchart TD

    A[Störung]
    B[1st Level]
    C{Gelöst?}
    D[2nd Level]
    E[3rd Level]
    F[Abschluss]

    A -->|melden| B
    B -->|Analyse| C
    C -->|Ja| F
    C -->|Nein| D
    D -->|weiter prüfen| E
    E -->|Lösung| F

    classDef level2 fill:#AB47BC,color:white
    classDef level3 fill:#EF5350,color:white
    classDef finish fill:#66BB6A,color:white

    class B level1
    class D level2
    class E level3
    class F finish

    10. Komplexer Projektablauf mit mehreren Verzweigungen

    flowchart LR

    A[Projektstart]
    B[Anforderungsanalyse]

    C{Budget ok?}
    D{Ressourcen verfügbar?}

    E[Projektplanung]
    F[Budget anpassen]
    G[Ressourcen beschaffen]

    H[Umsetzung]
    I[Test]
    J{Abnahme?}

    K[Go Live]
    L[Nacharbeiten]

    A -->|Start| B
    B -->|Prüfen| C

    C -->|Ja| D
    C -->|Nein| F

    F -->|neu bewerten| C

    D -->|Ja| E
    D -->|Nein| G

    G -->|erneut prüfen| D

    E -->|freigegeben| H
    H -->|fertig| I
    I -->|bewerten| J

    J -->|Ja| K
    J -->|Nein| L
    L -->|erneut testen| I

    classDef start fill:#4CAF50,color:white
    classDef process fill:#2196F3,color:white
    classDef decision fill:#FF9800,color:white
    classDef warning fill:#F44336,color:white
    classDef success fill:#8BC34A,color:black

    class A start
    class B,E,H,I process
    class C,D,J decision
    class F,G,L warning
    class K success
